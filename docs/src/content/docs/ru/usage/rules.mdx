## Как работают правила

Koala Clash не обязательно отправляет весь трафик через прокси. Для каждого соединения правила решают,
куда оно пойдёт:

- в **группу прокси** — через сервер;
- в `DIRECT` — напрямую, как без VPN;
- в `REJECT` — соединение блокируется.

Правила проверяются сверху вниз, срабатывает первое подходящее. Основные правила приходят с
подпиской, а свои можно добавить поверх них.

Текущий список правил — на странице **Правила** в боковом меню. Поле **Фильтр** ищет по нему.

## Добавить своё правило

<Steps>

1. Откройте **Правила** и нажмите карандаш **Редактировать правила** в шапке. Тот же редактор есть в
   меню профиля **⋮** → **Редактировать правила**.

2. Выберите **Тип правила** и введите **Параметр правила** — домен, имя процесса, IP и т. д.

3. В поле **Прокси** выберите, куда отправлять трафик: группу прокси, `DIRECT` или `REJECT`. Новое
   правило по умолчанию указывает на `DIRECT` — не забудьте поменять, если нужен прокси.

4. Нажмите **Добавить правило в начало**, чтобы правило сработало раньше правил подписки. **Добавить
   правило в конец** ставит его после них.

5. Сохраните изменения.

</Steps>

<Aside type="caution" title="Выбирайте группу, а не конкретный сервер">
  Если правило указывает на конкретный сервер, например «Frankfurt 2», конфигурация сломается, когда
  этот сервер пропадёт из подписки. Указывайте группу прокси и меняйте сервер внутри неё.
</Aside>

## Частые случаи

| Что нужно | Тип | Параметр | Прокси |
| --- | --- | --- | --- |
| Сайт через прокси | `DOMAIN-SUFFIX` | `example.com` | группа прокси |
| Игра или программа через прокси | `PROCESS-NAME` | `game.exe` | группа прокси |
| Программа в обход прокси | `PROCESS-NAME` | `discord.exe` | `DIRECT` |
| Подсеть в обход прокси | `IP-CIDR` | `192.168.0.0/16` | `DIRECT` |

`DOMAIN-SUFFIX` покрывает сам домен и все его поддомены, `DOMAIN` — только точный адрес.

Имя процесса игры или программы можно найти в диспетчере задач (вкладка «Подробности») или на вкладке
[Подключения](../connections-logs/): там видно, какой процесс открыл соединение и какое правило
сработало.

## Типы правил

Редактор поддерживает все типы правил Mihomo. Чаще всего нужны эти:

| Тип | Совпадает, если |
| --- | --- |
| `DOMAIN` | домен совпадает полностью |
| `DOMAIN-SUFFIX` | домен или его поддомен |
| `DOMAIN-KEYWORD` | домен содержит слово |
| `DOMAIN-REGEX` | домен подходит под регулярное выражение |
| `GEOSITE` | домен из категории GeoSite, например `youtube` |
| `GEOIP` | IP-адрес из страны, например `RU` |
| `IP-CIDR`, `IP-CIDR6` | IP-адрес назначения в подсети |
| `DST-PORT` | порт назначения |
| `PROCESS-NAME`, `PROCESS-PATH` | имя или путь процесса |
| `NETWORK` | протокол: `tcp` или `udp` |
| `RULE-SET` | совпадение с внешним набором правил |
| `AND`, `OR`, `NOT` | логическая комбинация других правил |
| `MATCH` | всё остальное, ставится последним |

Полный список и синтаксис — в [документации Mihomo](https://wiki.metacubex.one/en/config/rules/).

Для IP-правил есть опции **Не выполнять DNS-резолвинг (no-resolve)** и **Сопоставлять с исходным IP
(src)**.

## Где хранятся свои правила

Свои правила хранятся отдельно от подписки, в файле правил профиля, и применяются поверх неё при каждом
запуске ядра. Поэтому **обновление подписки их не удаляет**.

Правило из подписки тоже можно отключить кнопкой **Удалить правило**: оно попадёт в список удалённых,
и его можно вернуть кнопкой **Восстановить правило**.

В режиме **YAML-редактор** тот же файл правится текстом:

```yaml
prepend: # в начало, до правил подписки
  - DOMAIN-SUFFIX,example.com,Proxy
  - PROCESS-NAME,discord.exe,DIRECT
append: # в конец, после правил подписки
  - IP-CIDR,10.0.0.0/8,DIRECT
delete: # правила подписки, которые нужно убрать
  - GEOSITE,category-ads-all,REJECT
```

<Aside>
  **Редактировать файл** в меню профиля меняет сам конфиг подписки — такие правки перезапишутся при
  обновлении. Для правил используйте редактор правил.
</Aside>
